# 내부 식별자 노출 정책 (UNC-247)

- 상태: 결정됨
- 날짜: 2026-08-07
- 관련 이슈: UNC-234 (부모), UNC-247 (이 결정), UNC-250 (프롬프트 반영)

## 맥락

부모 이슈 UNC-234는 Uncommitted가 생성하는 카드 슬롯(`story.json`)과 캡션(`caption.txt`)의 "고도"를 높이는 작업이다. 지금은 같은 사실이라도 개별 티켓 키나 내부 화면·모듈 이름이 그대로 문구에 박혀 나올 수 있다 — 예를 들어 `FeedbackModal`이 입력 중에 끼어들지 않도록 고친 작업이 `FeedbackModal이 입력 중에 끼어들지 않게 고쳤다`처럼 고유명사 그대로 노출되는 식이다. 이런 문구는 이 프로젝트를 모르는 독자에게는 맥락 없는 내부 용어로 읽히고, 부모 이슈가 개별(individual) 프레이밍의 대표 사례로 지목한 형태이기도 하다.

부모 이슈의 목표는 이런 개별 사실을 지어내지 않으면서 누구나 아는 보편(universal) 상황으로 다시 서술하는 것이다. 이 문서는 그 목표를 이루기 위해 "공개 산출물에 내부 식별자를 어디까지 남길 것인가"를 결정한다. 이 결정은 Task 4(UNC-250)에서 프롬프트 지시문에 그대로 반영된다.

## 선택지

- (a) 전면 마스킹
- (b) 티켓 ID만 제거하고 화면·모듈 이름 허용
- (c) 현행 유지

## 결정

**(a) 전면 마스킹을 채택한다.**

1. UNC-234의 목표 자체가 개별 → 보편 프레이밍이다. `FeedbackModal`을 그대로 출력하는 것은 부모 이슈가 명시적으로 "개별"의 예시로 든 형태다 (부모 이슈의 개별/보편 대조표).
2. 부모 이슈 Implementation Notes: "자동 게시로 가면 (c)의 리스크가 커진다" — 현행 유지는 배제된다.
3. (b)(티켓 ID만 제거, 화면 이름 허용)는 카드에 내부 화면 이름이 크게 박히는 문제를 해결하지 못한다. 카드 슬롯은 캡션보다 글자가 크고 시선이 집중되므로 노출 비용이 더 크다.
4. 마스킹은 **사실을 바꾸지 않는다.** 사건은 그대로 두고 이름만 보편 서술로 바꾸는 것이므로 지어내기 금지 규칙과 충돌하지 않는다.

## 정책

**내부 식별자**란: 티켓 키(`UNC-123`, `ABC-45` 형태), 내부 화면·모듈·클래스·파일 이름(`FeedbackModal`, `diary-generator.ts`, `buildCaptionInstructions`), 내부 브랜치·PR 제목에만 등장하는 고유명사를 가리킨다.

**내부 식별자가 아닌 것**(허용):

- 통용 약어(`CI`, `PR`, `API`, `UI`, `AI`, `JSON`, `URL`)
- 공개 도구·언어·플랫폼 이름(`Git`, `TypeScript`, `Instagram`)
- 해시태그 토큰(`#`으로 시작)

**규칙**: 공개 산출물(story.json 슬라이드 문구, caption.txt)에 내부 식별자를 그대로 출력하지 않는다. 대신 그것이 가리키는 **보편 상황 서술**로 바꾼다.

예: `FeedbackModal이 입력 중에 끼어들지 않게 고쳤다` → `사람이 뭘 입력하는 중에 튀어나오는 모달`.

**적용 지점**: 프롬프트 지시문 (`buildDiaryInstructions()`, `buildCaptionInstructions()`). 이 정책은 프롬프트 레벨 지시이며, 사후 정규식 마스킹 필터를 추가하는 것은 이 이슈 범위 밖이다 (아래 "향후 과제" 참고).

## 기록 위치에 대한 주석

부모 이슈 AC4는 이 정책이 "`CLAUDE.md` 또는 관련 문서"에 기록되면 충분하다고 허용한다. 그런데 이 저장소의 `CLAUDE.md`는 `AGENTS.md`로의 심볼릭 링크이고(`ls -la CLAUDE.md`로 확인 가능), `AGENTS.md`는 자동화가 절대 수정하지 않는 잠금 파일이다. 따라서 이 정책은 `CLAUDE.md`를 편집하는 대신 이 spec 문서에 기록한다.

## 향후 과제

이 정책은 프롬프트 지시문 레벨에서만 적용된다. AI 프로바이더가 지시를 어기고 내부 식별자를 출력할 가능성 자체를 코드로 차단하는 사후 정규식 마스킹 필터(생성된 `story.json`/`caption.txt`를 다시 스캔해 티켓 키·내부 파일명 패턴을 걸러내는 검증 단계)는 이 이슈의 범위 밖이다. 실제 생성 결과에서 프롬프트 지시만으로 충분한지 관찰한 뒤, 누락이 반복되면 별도 이슈로 다룬다.
